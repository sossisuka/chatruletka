# Проверка приложения

Дата: 10 сентября 2026. Среда: Windows, Node.js 24.16.0, Next.js 16.3.4, Chromium.

## Результаты

- Production-сборка `npm run build`: успешно.
- TypeScript `npm run typecheck`: успешно.
- ESLint `npm run lint`: без ошибок и предупреждений.
- Серверные интеграционные тесты `npm test`: 12/12, включая проверку публичного Origin.
- Браузерные тесты `npm run test:e2e`: 8/8 на production-сборке, 21.2 секунды.
- `docker compose --profile public --profile turn config --quiet`: успешно.
- `/api/health`: HTTP 200, реальные счётчики активных соединений.
- agent-browser: страница загружается, основные элементы доступны, ошибок браузера не обнаружено.
- Desktop 1440×1100 и mobile 390×844: визуально проверены; горизонтального переполнения на mobile нет.
- Публичный адрес `http://185.128.200.106:3005`: Socket.IO подключается, показывается реальный онлайн и предупреждение о необходимости HTTPS для камеры.
- Dev-сервер: HMR и Socket.IO одновременно поддерживают WebSocket с `Origin: http://185.128.200.106:3006` и соответствующим Host. Соединения оставались открыты после 2.5 секунд.
- Анимации индикатора и диалога активны по умолчанию и отключаются при `prefers-reduced-motion: reduce`.

## Проверенные сценарии

Сервер: ожидание первого посетителя, уникальная пара, двусторонние фильтры страны, изоляция сообщений и SDP, отклонение поддельных и устаревших сессий, следующий собеседник, отсутствие немедленного повторного подбора, очистка очереди после Stop/disconnect, временная блокировка, лимиты сообщений, проверка Origin/Referer, подписанные временные TURN-ключи.

Браузер: независимые контексты устанавливают WebRTC и получают воспроизводимое видео ненулевого размера и живые аудиотреки. Проверены двусторонние сообщения и безопасный вывод HTML как текста, микрофон/камера, освобождение media tracks по Stop, третий участник и Next, очистка черновика после Next, фильтр страны, отказ в разрешениях, Stop во время ожидания разрешений и мобильные диалоги.

Устройства в автоматических проверках синтетические. Очередь, Socket.IO, WebRTC и обмен медиаданными не подменены. Только тесты ошибок доступа и позднего разрешения намеренно переопределяют getUserMedia.

## Что не проверено

Docker Engine не запущен: синтаксис Compose проверен, контейнерная сборка не выполнена. HTTPS-сертификат для внешнего IP не выпущен. На порту 80 внешнего адреса отвечает nginx, сертификат на 443 не проходит проверку имени IP. Настройка nginx требует доступа администратора к внешнему серверу; файлы подготовлены в `deploy/`. Проверки не подтверждают работу внешнего TURN или передачу с физических камер. На внешнем HTTP браузер не предоставляет getUserMedia — этот адрес пока не подходит для видеозвонков.

Production-сервер оставлен работающим на http://localhost:3005. Порт 3000 уже был занят другим проектом.
